# 画面要素と実測スタイルの照合

[画面ごとの要素一覧](../README.md)の「実測」リンクから、同じ安定IDの実測スタイルを開けます。要素のDOMを確認できたテーマごとに、一件ずつ採取例を表示します。枠と余白は上・右・下・左、間隔は行・列、寸法は幅・高さの順です。四辺が同じ枠は値を一回表示します。古い採取形式に列がない場合は `—` で表示します。フォント名はブラウザーが返したフォールバック列で、実際に個々の文字に使われたフォントの特定は対象外です。

各例の画像は採取時の画面全体です。生データの `elements[n]` でDOMのキー・状態・矩形を、`styles[n]` で当該要素のcomputed styleを確認できます。スタイルの列名は同じ生データの `properties` に並びます。両配列の添字は0始まりです。擬似要素は、元のDOM要素と擬似要素用のスタイルを参照します。一部の状態はcomputed styleのみを収集しました。[採取マニフェスト](../evidence/manifest.json)

## 照合できる範囲

- 対象の画面と状態を限定し、ブラウザーで評価したセレクターの一致結果か、採取DOMのタグ・ID・クラス・属性・親子関係で一致を証明できる要素を記録します。
- 共通シェルの項目にはKanban・List・Groupフレームも使います。ホームのボード作成操作にはボード0件を確認した新規作成フレームも使います。複数の意味で同じセレクターを使う項目は、要素ID別に画面状態を指定しています。
- 保存されたDOMで証明できる範囲だけを照合します。採取時に閉じていた領域、モーダルの背面、収集対象外のブラウザー描画と、未採取の状態があります。矩形が表示領域と交差していても、クリッピングや重なりで画像上に見えない部分があります。
- 生データと照合できない項目には実測値を記入しません。未観測は、この採取セットから一致を確定できなかった場合を含みます。ソース上のCSSは画面別一覧に残しています。
- 同一のMarkdownを6箇所で表示した追加採取では、取り消し線の記法が平文として表示されました。取り消し線のDOM要素は未観測として記録しています。[追加採取の結果](../evidence/manifest.json)

## 再生成

リポジトリで `node scripts/ui-catalog-observations.mjs` を実行すると、画面別一覧と採取マニフェストからこのディレクトリの画面別Markdown・JSONを再生成します。生成前に実測JSONと原画像のSHA-256を照合します。`--check` を付けると生成内容の一致を確認します。JSONの `method` はブラウザーのセレクター評価（`browser-query`）または採取DOMによる照合（`captured-dom`）を表します。`frames` は一致を記録した全フレーム、`items` はそれぞれのフレームに含まれる要素・スタイルの添字です。
