# UIスタイルの保守性評価

基準は `2ff8489d889706a6dc6392fd28aeff073e0b515c`。既存の6変更単位は、見つかった表示差の是正と同じ責務の宣言整理を進める第一段階として妥当です。継続的に揃えるには、入力型・状態・テーマを受け持つ定義を明示し、利用画面のうち変化しやすい条件を回帰検証で守る必要があります。[共通定義案](shared-components.md) · [スタイル比較](style-comparison.md)

ソースのCSSは機能別に分かれ、製品ビルドでは `styles.css` を一つの入口として束ねます。評価するのは、ある変更を適用する定義が複数に分かれているか、別の役割に意図せず効くか、結果を既存テストで確認できるかです。以下の「変更に必要な定義」は、記載した範囲の変更を仮定してコードを読んだ結果です。「影響確認」は、コードの編集を前提にしない利用箇所です。実装後の値や作業量は推定していません。[CSSの読み込み順](../style-source.md) · [ビルド入口](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/scripts/build-web.mjs#L9)

## 1. 標準コントロールの内余白を変更する

- **変更に必要な定義**　標準の文字入力とネイティブselectは `forms.css`、標準ボタンとファイル選択ラベルは `components.css` に既定の余白があります。文字サイズ、行高、角丸は既にトークンを共有します。カスタムビューのselect、サイドバーのボード・タグ作成入力は別の余白指定を持つため、標準の対象に含めると決めたものだけ定義を揃える必要があります。6単位の宣言整理後も、標準・小型・アイコン・ボード初回案内でどの寸法を共有するかを登録する余地があります。[入力の既定値](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/styles/forms.css#L1) · [ボタンとラベル](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/styles/components.css#L1) · [トークン](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/styles/tokens.css#L42) · [入力寸法の実測](style-comparison.md#text-input)
- **影響確認**　明暗と狭幅で、編集・移動フォームとツールバーの折返し、ネイティブselect、アイコンとファイル選択ラベルの高さを確かめます。ツールバー高はJSで計測して共有するため、CSSを変えても計測コードの変更は不要で、位置復帰の結果を守ります。既存E2Eは基礎文字サイズと一部の狭幅レイアウトを確認します。対象の余白だけを可視差として追加で測定できます。[ツールバーの計測](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/app-filters.js#L29) · [文字のE2E](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/test/e2e/layout-visual-system.spec.ts#L69) · [狭幅のE2E](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/test/e2e/completion-archive-filters.spec.ts#L138)

## 2. フォーカスと無効状態の表現を変更する

- **変更に必要な定義**　通常入力は `--control-focus-ring` と枠色を共有します。初回案内でも `--attention-ring` が同じ値を参照するため、入力だけの強調変更なら適用先を確認して分離します。検索・ピッカーは外枠の `:focus-within`、一覧のタイトルやGroupリンクは `:focus-visible` のoutline、スイッチは隣接する表示要素を強調します。無効状態を揃える場合はGroupのボタン、タグ色フォーム、外部課題取り込みを共通の見た目に接続し、入力型や表示状態ごとの責務を残します。[通常入力とリング](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/styles/forms.css#L51) · [注目リングの参照](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/styles/tokens.css#L84) · [検索枠](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/styles/toolbar-filters.css#L46) · [スイッチ](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/styles/toggles.css#L76) · [Groupとタグの無効状態](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/styles/groups.css#L435) · [タグ入力](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/styles/sidebar-tags.css#L120)
- **影響確認**　キーボード操作、強制カラー、開閉後のフォーカス復帰、通信中の無効化と復帰を確かめます。外部取り込みの送信可否やGroup保存中の `disabled` はJSで状態を計算するため、色・枠の変更ではこの処理を維持します。既存E2Eは新規編集の入力・textarea・selectの枠の一致、一覧タイトルの強制カラー、Group保存中の無効化を守ります。外部取り込みのネイティブチェックと親ラベルのフォーカス、送信中の配置は対象箇所で確認する価値があります。[外部取り込みの状態](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/app-editor-remote-import.js#L30) · [編集フォーカス](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/test/e2e/layout-visual-system.spec.ts#L121) · [強制カラー](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/test/e2e/ticket-view-styles.spec.ts#L18) · [Group保存](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/test/e2e/group-partial-render.spec.ts#L139)

## 3. 暗色の前景と入力面を変更する

- **変更に必要な定義**　チケットダイアログの本文の継承を直す場合、前景色を持つUXダイアログに合わせ、チケット枠で既存の `--text` を参照するのが最小の変更です。操作入力の暗色面を一括で変える場合は別です。基本の `--control-bg` とダーク側の `--surface-inset` 参照が並存し、後から読み込まれる `dark-mode.css` に広い入力セレクターがあります。外部取り込みのチェック欄は幅の指定とラベルレイアウトも重なるため、専用の配置を直した後に、入力面を持つ型に基礎と暗色の対象を揃える責務を持たせます。[ダイアログの前景と面](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/styles/dialog-shell.css#L1) · [暗色の入力指定](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/styles/dark-mode.css#L26) · [暗色履歴の実測](style-comparison.md#activity-timeline) · [チェック欄の実測](style-comparison.md#checkbox)
- **影響確認**　既定文字、補足・警告、ハイライトコード、透明な子の合成後の背景、ボタン・無効入力、モーダルと非モーダルの両枠を確認します。履歴本文は暗色で黒、背景との比は約1.23:1でした。既存の優先度・状態の強調やトーストの面のテストに加え、暗色履歴本文と背景を代表箇所として検証すると継承漏れを検出できます。全画面の色一覧を保存する必要はありません。[既存のトーストと編集枠の検証](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/test/e2e/layout-visual-system.spec.ts#L90)

## 6. 本文の差分ビューの区切り線を変更する

- **変更に必要な定義**　差分行の下線と行頭マーカーの右線に `1px` を指定していますが、両方が参照する `--border` に公開ソース上の定義やフォールバックがありません。暗色の採取では非最終行の下線幅、マーカーの右線幅とも `0px` です。線を使う意匠なら既存の境界トークンへの接続を候補とし、線を使わないなら無効な宣言を整理できます。[行とマーカーの指定](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/styles/ticket-detail.css#L266) · [実測JSON](../evidence/styles/ja-dark-ticket-detail-remote-diff.json)
- **影響確認**　最終行、追加、削除、変更なしの識別、狭幅での折返しとスクロールを確かめます。差分データやMarkdown変換には手を加える必要はありません。トークン名の参照解決を検査すると同種の漏れを見つけられます。検査ではJSが実行時に設定する `--shared-toolbar-height` や有効なフォールバックを区別します。[実行時の変数設定](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/public/app-filters.js#L57)

## 変更の順序と継続運用

1. **既知の表示差を先に修正し、回帰を絞って検出する。** 6単位のうち履歴文字、外部取り込み、Markdownリンク、翻訳は、利用者が確認できる差を先に検証します。既存のPlaywrightの明暗・フォーカス・保存結果の検証を使い、穴がある履歴の文字色、リンクの適用先、チェック欄の配置と送信値を対象のテストに加える候補とします。標準の `pnpm lint` はOpenAPI向けで、トークン参照の検査は別の役割です。[パッケージのチェック定義](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/package.json#L10) · [CIの検証](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/.github/workflows/verify.yml#L33)
2. **標準の宣言と用途差の置き場所を定める。** トークンは色・寸法の語彙、基本ルールは対象となる入力型と状態、画面側は密度・配置と局所バリアントを持ちます。通常と暗色で同じ対象が変わるようにし、広い子孫セレクターや同じ規則の追加が必要になった場合は責務を再確認します。共通化によって編集箇所が減り、既存の状態・読み上げ・フォーカスを維持できるものから進めます。仮想行の位置、領域間の操作差、任意色の契約まで同時に変わるなら、共通化の境界をヘルパー・色の語彙・同値宣言まで戻します。
3. **カタログを差分レビューに使う。** 既存の再生成チェックは、実測の出典・ファイルのハッシュと索引・比較表の整合を確認します。現在の製品の描画を再計測する処理は含まず、標準チェックにも接続されていません。カタログ変更時の生成チェックと、UI変更時に影響を受ける要素・状態の比較を別に行うのが適切です。旧採取を固定したまま、対象シナリオのbefore/afterを各製品版の証拠として記録します。現行の照合は異なる基準版を混在させないため、新版の証拠で既存索引を更新する場合は同じ基準版の採取と一覧を揃えます。[実測の再生成手順](../observations/README.md) · [カタログの索引と更新手順](../README.md)
