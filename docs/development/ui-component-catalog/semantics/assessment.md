# 部品数の妥当性評価

このページは棚卸し行数と意味分類の評価です。今後の保守性・デザイン統一性を含む共通化方針は[追加評価](architecture-assessment.md)に記録しています。

## 何を数えていたか

1,301は21画面・領域の棚卸し行数であり、独立した再利用部品の種類数ではありません。画面別の登場、部品の内部要素、状態違い、ブラウザー別の疑似要素も含みます。スタイルの適用箇所を追跡する調査単位としては役立ちますが、製品の部品数や複雑さの指標としてそのまま利用するのは不適切です。

| 棚卸しの例 | 行数に含まれるもの | 意味としての扱い |
| --- | --- | --- |
| Markdown表示 | 6文脈×35要素＝210行。見出し、表セル、コードなど。うち6行の取り消し線はこの版では生成されない | リッチテキスト表示の内部要素と利用文脈。210種類の独立部品ではない |
| 上部の検索欄 | 共通シェル、Kanban、Listに同じselectorの入力が登場 | 同じ検索部品の画面別利用 |
| Groupの進捗表示 | progress本体とWebKit用2種類、Firefox用1種類 | 1つの進捗表示のブラウザー別内部表現 |
| トースト通知 | 通常通知、エラー通知 | 通知部品の状態違い |
| タグ選択 | 17行。検索欄、選択済みチップ、候補行、色見本、アイコンなど | 複合的な選択機能と、その内部で利用する基本部品 |

同一selectorを単純に除いた値は1,130、描画元ファイルと行の組は702です。しかし、同じ意味でもselectorが異なる場合や、一行のテンプレートに複数部品が含まれる場合があります。これらも再利用部品数の代わりにはなりません。画面別利用・内部要素・selector・描画元という数え方は対象が重なるため、1,301から順に差し引いて部品数を算出しません。

## 分類と判定の基準

意味の分類と、現在の実装が共通であるかは分けて記録します。全棚卸し行のIDを残し、機能のまとまり、部品の役割、内部構成、状態・用途の違いを追跡します。ボタン、入力、選択などの基本部品は機能をまたいだ比較対象にします。

- **共通化に向くもの**：情報や操作の契約が同じで、画面ごとの違いを明示的な状態・用途の違いとして説明できるもの。
- **専用の構成を保つもの**：課題の親子関係、完了した親の参照表示、段階表示、外部本文との差分など、機能固有の意味・操作を持つもの。内部の基本部品は共用できます。
- **一括化しないもの**：見た目が似ていても、一覧の選択チェックとMarkdownの読み取り専用チェック、関係の解除と永久削除など、意味や影響の異なるもの。
- **部品数に含めないもの**：この版で描画されない表現。未観測と非生成は区別し、未観測だけを理由に存在しないと判断しません。

分類後の群数も、そのまま新規作成する実装ファイルやコンポーネントの数にはしません。既存の共通CSS・描画処理で十分なものは維持し、重複や変更の不整合がある部分を優先して標準化します。

この評価では製品コードを変更していません。部品数の削減目標やCSSファイル数の目標は設定しません。

## 妥当性の判断と次の比較対象

- **1,301行を調査記録として残すことは妥当です。** 同じ部品でも、画面・状態・テーマで適用スタイルが変わるため、利用箇所への追跡が必要です。ただし、利用者向けのカタログ入口は意味群にまとめ、1,301行を同じ重みで並べて設計判断を求める構成は避けます。
- **1,301種類の独立部品として扱うことは不適切です。** 現在の分類では内部要素と配置用の構造が大きな割合を占めます。ボタンのアイコンや表のセルまで個別の再利用コンポーネントにする必要はありません。
- **81の比較群は調査上の整理として妥当ですが、実装の分割数にはしません。** 現行の共有を確認できる19群、画面横断で比較する23群、同領域内で比較する15群、文脈固有の24群に分けています。比較対象の38群は、不具合や重複が確定した38群という意味ではありません。
- **共通化は基本部品から評価します。** アクションボタン、入力、選択、ラベル、状態メッセージ、タグ・優先度・課題識別の表示について、同じ役割・状態・テーマでスタイルを比較します。既に共有されているMarkdownや関係候補などは、別部品として作り直しません。
- **画面固有の複合構造は維持します。** Kanbanカード、Listの行、Groupの階層行は、ドラッグ・選択・字下げ・仮想表示などの契約が異なります。共通の情報表示は揃えつつ、行全体を無理に一種類へ統合しません。

製品が過剰に1,301部品へ分割されているという結論にはなりません。問題を判断すべき単位は、意味が同じ基本部品の定義が散らばっているか、共通の見た目や状態変更を一か所で管理できるかです。次の工程では、この分類を基準に実測スタイルと実装の重複を照合します。
