# デザインの統一性と今後の保守

現在のKanbaloneには、明暗で共通の色・文字・余白のトークン、共有レンダラー、既存のUIレビューとブラウザーテストがあります。差が残りやすいのは、共通部品と画面側のどちらが見た目を決めるかが曖昧な箇所です。例えば、チケットダイアログの前景色の継承、文字入力の規則のチェック欄への適用、同じMarkdown内のリンク色にその影響が出ています。6変更単位は第一段階です。今後の画面で再発しにくくするには、部品の選び方と用途差の境界を短い現行仕様にし、新画面が実際にその共通定義を利用する形まで整えます。[6変更単位](shared-components.md) · [実測の差分](style-comparison.md) · [実装・保守方針の全体評価](architecture-assessment.md)

対象は基準 `2ff8489d889706a6dc6392fd28aeff073e0b515c` の21領域、1,301行、13用途・81比較群です。比較対象38群のうち20群は既存共有を継続、9群は用途差を維持、4群は共用候補、1群は表示是正、4群は観測不足という判断です。これらは比較群の判断で、独立したコンポーネントや必要な修正の件数を示すものではありません。[意味別分類](taxonomy.md) · [比較の条件と結果](style-comparison.md)

## 操作状態の契約

現在のCSSと観測で確認できる範囲から、新規または変更する操作に使う基準を定義します。状態を組み合わせる場合は、同じ操作のどの状態同士を比較するかを記録します。

| 状態 | 現状の根拠と境界 | 共通の表示と確認 |
| --- | --- | --- |
| 通常 | 主操作、通常、アイコン、危険、破壊的確定は既存クラスで表現。同名のタグでも読取、解除、設定開始は操作結果が異なる。 | 意味に合う既存クラスとHTML種別を選ぶ。ラベルと操作範囲が表示だけで分かる状態を起点とする。 |
| hover | ボタン枠、リンク、行で局所規則がある。Kanban上のhover観測はあるが、全基本型のhover比較は揃っていない。 | 元の意味を変えず、枠・背景・下線などでポインター位置を示す。押下できない操作に通常のアクションの強調が出る場合は用途別に確認する。 |
| フォーカス | 入力の境界とリング、Groupのoutline、リストのクリップを避ける内側のoutlineなど、同じトークンでも適用部位が異なる。 | キーボードで到達した操作・入力が見える。検索・タグのように外枠へ出す場合は `:focus-within` を使い、選択中とフォーカスを並存して識別できる。既存のforced-colors用指定やネイティブ入力の可視フォーカスを保つ。 |
| 無効 | Group・外部連携などに局所のdisabled外観がある。読取専用の本文や内容の状態記号とは意味が異なる。 | 真に操作不可ならネイティブの `disabled` 等で動作と表示を揃える。読取専用では内容・コピー・リンクの利用に必要な操作を残す。見た目の薄さだけで無効化したように示す上書きを避ける。 |
| 読込中・保存中 | 関係候補は取得状態と再試行、チケット編集とコメントは保存状態を持つ。送信中には抑止する操作が用途ごとに異なる。 | 入力や既存結果を必要な間保ち、意図しない再送や対象の切替を防ぐ。状態の文言と、抑止する操作を明示し、前後の位置を測る。 |
| エラー | 設定行、候補、ダイアログ、トーストなどに表示経路がある。失敗した場所と、どこから復帰できるかが経路により異なる。 | 入力や項目に結び付くエラーはその近くに置く。エラー本文と記号には既存の `--danger` を使い、再試行や取消は操作自体の意味に合ったボタンで示す。短命の全体トーストだけで入力の修正箇所を伝える設計を避ける。 |
| 選択済み・現在地 | タブ、フィルター、ボード、Group、チェックで選択の意味が違う。選択中・現在地・キーボードで指している候補をCSSの `.active` が使う場合がある。 | アクセントを使って状態を示す。ARIAやネイティブの `checked`／`indeterminate` は実際の意味に合わせる。現在地、選択値、キーボードのフォーカスが独立に伝わるようにする。 |

この表の基準は状態の照合点を示します。コメントのリモート送信は成功済み・失敗と理由の展開を観測しています。送信中や再試行から保存までの系列、関係候補の取得中、全ボタンのhoverなどは同条件の比較が揃っておらず、未確認です。[視覚テスト](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/test/e2e/layout-visual-system.spec.ts#L121) · [タイトルのフォーカス](https://github.com/wamukat/kanbalone/blob/2ff8489d889706a6dc6392fd28aeff073e0b515c/test/e2e/ticket-view-styles.spec.ts#L18) · [観測範囲](../evidence/README.md)

## 新画面で選ぶ標準と用途差

既存クラスや描画関数の利用を入口とし、下の「定義元」が部品内の既定値を持ちます。画面側は部品を置く場所、コンテンツ量、既に説明された用途差を指定します。同じ目的の部品を足す場合、最も近い既存パターンと比較し、新しい指定が必要になる理由を短く記録します。以下は今後の契約案です。

| 基本型 | 既存の標準と定義元 | 用途差を認める境界 | 避ける上書きの例 |
| --- | --- | --- | --- |
| Button | `components.css` のボタン下地。通常、`.primary-action`、`.ghost`、`.danger`、`.danger-confirm-action`、`.icon-button` を役割で選ぶ。 | 表やツールバーの小型、アイコンとラベルの組合せ、ダイアログのミニ操作。ファイル選択はラベルを維持。 | `.new-pane button` で面・色・角丸をまとめて上書きし、主操作と破壊的確定が同じに見える。 |
| 文字・検索・複数行入力 | `forms.css` の型を限定した文字入力・textareaと共通の面、枠、文字、リング。 `app-inline-text-form.js` は短い名前入力の挙動を担当。 | 幅・行数・折返しは入力する内容に合わせる。検索やタグの可視フォーカスは外側の枠で示し、中央操作と候補選択は分ける。 | `.new-form input { width: 100%; … }` をチェック、ラジオ、色、ファイル、hidden入力まで広げる。 |
| Select | `forms.css` と画面に既存のネイティブselectを使う。値の基本文字とラベルの強調を区別。 | 表示条件、フォーム入力、順序指定の幅とラベル。無効、空選択、値欠損、再取得を機能側で扱う。 | 太字ラベルの指定を値へ継承させる1画面だけの上書きや、同じ選択機能の自作メニュー。 |
| Check・Radio | ネイティブ入力を起点に、既存のラベルや制御を組み合わせる。 `toggles.css` と `app-ux-color-field.js` は任意色の既存スイッチを担当。 | Listの行選択と部分選択、設定の選択肢、プロバイダー選択のボタン型ラジオ。配置やラベルとの間隔は用途に合わせる。 | 入力全域への `appearance: none`、チェックボックス本体への文字入力枠、フォーカスを示さずに `outline: none`。 |
| Dialog | `dialog-shell.css` の面・前景・影・枠。既存のチケットは `app-dialogs.js`／`app-editor.js`、確認は `app-ux.js` が表示・閉じ方を持つ。 | 非モーダルの編集とモーダルの確認で、背景・スクロール・ドラッグ・リサイズ・フォーカス復帰を用途ごとに持つ。 | 固有の編集ダイアログへ `showModal()` を適用する、配下の全ボタン寸法を同じにする。 |
| 文字・メタ情報 | `tokens.css` の文字階層、 `.muted`、既存のメタ行。チケット詳細の面は `ticket-detail.css`、日時・補足のレイアウトは `comments-activity.css`。 | 日時、補足、ID、タイトルを圧縮する位置。改行・省略・表示順は内容で決める。 | 画面全体の `font-size` や前景を上書きしてラベル、本文、エラーまで同じ階層にする。 |
| Tag・状態・優先度 | `app-tags.js`、`app-ticket-status.js`、`app-priority.js` を値・色・記号の定義元とする。 | 読み取り表示、操作付きピル、解除チップ、設定ボタン、マスクアイコン。指定色やアーカイブ状態もそれぞれの意味を保つ。 | 背景色だけで優先度・完了・解除可否を伝える、タグ色付き表示に一律のローカル配色を適用する。 |
| Link・Tab・Feedback | リッチテキストリンクは `content-markdown.css` に範囲を置く方針。タブは `.detail-tab`、処理状態は `.editor-save-state`、全体の短い通知は既存トースト。 | タイトル・所属先・本文に含まれるリンクを区別。取消後に復帰する画面、差分・外部本文の切替、領域内エラーは固有。 | 全ての `a` の色を新画面から変更する、Tabの選択とフォーカスを同じ状態として消す、エラーを短命の通知へ移す。 |

新しい定義が必要な場合は、使う画面・部位、基本型、用途差、関係する状態、定義元を一緒に説明します。共通トークンや基礎ルールが変わる場合は、呼び出し元と別の画面への波及を調べます。既存の複合部品を選べる場合はその入力や描画を使い、単なる表現の近さを理由に操作契約まで共用することは避けます。

## 6変更単位の再評価と次の範囲

| 既存の単位 | 再評価 | 次の画面にも残す境界 |
| --- | --- | --- |
| 1. リモート取り込みチェック | 局所是正を維持。チェックの横並びとボックス、ラベルとSpace、模擬連携での値と保存を確かめる。 | 文字入力の面・横幅をチェックへ波及させない。チェックが値を変える場面はネイティブのラベルと状態を起点にする。 |
| 2. ダイアログ前景／Markdownリンク | 表示是正を維持。明暗の本文・補足・エラーと、共有Markdownの6文脈を対象にする。 | ダイアログは自身の前景を持ち、リンクの共通ルールはリッチテキストの範囲に限る。モーダル性とUI遷移は各経路のまま。 |
| 3. 最初のボード作成案内 | 翻訳への接続を維持。日本語・英語の案内と作成後に解除される状態を検証。 | 見える語句は翻訳処理から供給し、疑似要素には配置と装飾を割り当てる。 |
| 4. ボタン／入力の共有 | 同値の宣言と入力型の境界の整理を維持。セレクターを狭めて別の欄の表示が変わる場合は、対象ごとに是正か保留かを判断する。 | 基礎と標準密度は共有元へ置く。型を絞り、詳細度・読込順と既存のvariantを維持する。 |
| 5. 面／メタ情報 | 同じ宣言の整理を維持。コメント・活動・本文の面と、日時・補足の共通宣言が対象。 | 面、文字、コンテンツの状態を分け、空状態の情報量や各画面のレイアウトを保持する。 |
| 6. 並び順とコメント入力 | 同じ目的の値の太さと入力左右余白に限る。既存の見た目を意図的に揃える変更として扱う。 | 対応する部位と採用値を記録し、基礎宣言の整理や親の幅変更から分離する。 |

この6単位では、共通部品の選択方法、hoverから失敗までの表示責務、画面別上書きの影響範囲は自動では固定されません。次の段階では、新画面や変更される画面に効く順で進めます。

1. **現行仕様を小さく保つ。** 上記の基本型、用途差、状態、定義元を入口にし、既存UIレビューから判断をたどれるようにする。追加する画面はまず用途を当てはめ、同じ役割の比較対象、必要な用途差、変更の影響先を説明する。
2. **再発しやすい境界から検査する。** 既存のChromium E2Eに、ダークの継承色、入力型の適用境界、投稿・編集や一覧・設定の同じ役割を、既存の代表テストを再利用して確認する。確認するのは役割に必要な色、余白、寸法、キーボード、状態と保存結果で、無関係なピクセル差やOSが決めるネイティブ描画は環境を添える。
3. **置換は変更箇所に合わせる。** 同じ宣言・役割を新設する場面や、既存の共通元を変更する場面から揃える。ナビの密度、未観測のフォーカス・失敗状態、仮想化を含む行全体は、それぞれ同条件の比較と機能検証が揃えば次の対象にする。

運用は、基準版で観測したカタログと、現在の実装で採用すべき短い契約の二つに分けます。カタログの1,301行と115フレームは観測時のSHAに対応する記録です。変更に該当する部品と利用画面だけを確認し、元の画像は基準版として参照します。変更後の仕様や保存結果は変更版で記録し、実測がない状態は未確認として持ち越します。[基準カタログと更新手順](../README.md)
