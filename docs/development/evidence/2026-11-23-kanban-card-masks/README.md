# Kanban カードのSVGマスク

[実装 PR #60](https://github.com/wamukat/kanbalone/pull/60)

基準は PR58 の`19ad93f2c6aa4be5cb8429d7e1b673bea97412aa` です。マージ済み main `2eb433d8c91af3e8d5b4c7c92071abcd26100eb1` とコミットツリーが一致します。Node 26.13.1、Chromium 159.0.8154.6、macOS x64 Intel i7を使用し、両版とも本番用ビルダーで配布資産を生成しました。専用の合成SQLiteを複製して比較しました。

試案は各Kanbanカードを保ったまま、階層3種、優先度4種、完了・アーカイブ2種、ブロッカー1種を同一オリジンのSVGマスクに変更します。SVGの元の子要素と線幅（状態2.4、その他2）は従来どおりです。色は親要素から継承し、既存のラベル、タイトル、ブロッカー数、操作部を使います。Groupと共通する5資産を再利用し、優先度とブロッカー用の5資産を追加しました。

## 小規模の外観と互換性

313枚を描画する1,000件ボードの英語ライトと、アーカイブを表示した約400枚の合成ボードの英語ダーク・DPR 2で比較しました。後者はブロックされた子チケットに実ポインターを乗せています。全画像を1440 × 1000 CSS pxで取得しました。設定、各アイコンの色/矩形/ラベル/タイトル、表示IDと順序、レーン高は一致しました。画素差はライト1,627画素、ダーク1,931画素で、いずれもアイコン矩形内、最大6/255でした。独立目視では親子、各優先度、ブロッカーと件数、アーカイブ、完了表示、カード位置に視認できる差はありませんでした。ダーク条件では新しいSVG 10件が全てHTTP 200でした。

120枚表示時にアニメーションフレームのコールバックを一時停止する検証で、強制色を切り替えてから描画を再開しました。追加バッチ、非アクティブの展開、Doneの次頁にも現在のSVG方式が適用され、強制色を解除すると対象アイコンのみマスクへ移りました。実際のSSEで別レーンのチケットを更新した際に、元のレーンのカード要素、フォーカス、40pxのスクロール、ラベルを保ちました。

実ポインターでカードとレーンをドラッグし、ブラウザの `DataTransfer.setDragImage` に渡る元要素を確認しました。レーンのクローンは高さ420px以内で、優先度とブロッカーが含まれます。Escによる中止後のチケット位置とレーン順をGETで照合しました。ヘッドレスのため、OSが表示するドラッグ画像の画素は取得していません。

小規模の原画像とSHAは `image-manifest.json`、画素比較は `appearance-comparison.json` に記録しています。これらは製品と同じ公開アセットを使った事前比較の結果です。

## 大規模ボードの冷間表示と実入力

同じ英語ライト、1440 × 1000で、各試行は新しいブラウザコンテキストを使用。3,013枚と3,005枚の各条件は現行と試案の実行順を反転し、それぞれ最初の1回を除いたn=2です。表示は対象DOMの検出後2アニメーションフレーム、マスクは全画像の転送を確認して2アニメーションフレームを待ちました。全件と画像を確認した終点は、全件DOMと画像確認の遅いほうです。

全SVG応答は各試行でHTTP 200、画像の最終応答自体は初期表示範囲のDOM確認＋2アニメーションフレームの計測終点より前です。DOMに最初のカードが挿入された時刻との前後関係は試行によって異なります。両版の共通指標である初期表示範囲のDOM＋2rAFは+4.5 msと+8.5 msでした。表の初期側の差+33 ms、+26 msは、試案だけに全SVG取得確認とその後2フレームを追加した参考値です。初回の見た目がこの分遅くなったことを示す値ではありません。最初の画面で目に見えるアイコンだけの画像取得や描画時刻は個別には計測していません。全件後に取得した原PNGと小規模の画像比較で表示を確認しました。

すべてのEnter試行で、ホストが発行する前から対象詳細が表示されて2アニメーションフレームが経つまでを測定しました。キーはすべて360枚描画中に配信され、同じチケットを開き、表示タイトルを保存GETと照合しました。両ケースの行内子要素は63,397→45,294、64,157→45,318。表示IDと順序、レーン高さ、画面内の初期範囲、カードと操作部の座標、タグHTMLは基準と一致しました。

生ログは `kanban-mask-screen.json` と `interaction-mask-screen.json`、集計は `screen-summary.json` です。

## 配布アセットと原画像

測定時と製品再ビルド時で、公開アセット全138ファイルを比較しました。公開ソースのSHA-256集約値は `e6719a1894160412de0d555bf355fc28b902071bf9df268c8a2042bb73f7acd4`、配布ツリーの集約値は `b4c740a6fb1b9bc93d8cc075f72697dc3b3091d859c630abcfe95999c225a249`。どちらも元試行と一致しました。HTMLは配布時のJS・CSSハッシュ差し替えを正規化して比較し、他のソースは配布ディレクトリのコピーとバイト一致しています。

追加の日本語ダーク390 × 844の原画像では、両版の313枚の表示順、スクロール高さ、階層ラベルが一致しました。画素差は613画素、最大2/255です。マニフェストは、日英の原PNGの寸法、SHA-256、比較条件を記録しています。原PNG10枚はすべてデコードし、寸法とSHA-256を照合しました。

## 再現条件

`docs/development/evidence/2026-11-23-tag-render/prepare.mjs` が作る既存の合成フィクスチャを使用しました。3,013枚と3,005枚のケース名は `kanban-10000` と `kanban-high-active` です。基準コミットと変更版の両方で `pnpm build` を使い、各版の `dist/public` を同じテスト用サーバーに配信します。既存のレンダーベンチで先頭・初期表示範囲・全件と2rAFを比較し、変更側では `PerformanceObserver` のresource entriesから6件または9件の同オリジンマスクを確認し2rAF後の時刻を採取しました。実入力は先頭カードの操作準備完了後、ホストがキーを発行する直前から詳細表示後2rAFまでの区間です。
