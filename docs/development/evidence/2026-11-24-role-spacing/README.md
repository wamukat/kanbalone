## 比較結果

- 保存済みビュー **Release desk** で「本文・コメントの更新が新しい順」を選んだ状態を撮影しました。変更後は一覧と設定の選択値がともに `font-weight: 400` で、設定のラベルと完了条件のセレクトは600です。一覧の原画像は両言語で変更前後のPNGバイトが一致しました。
- 英語の設定画面では、太さを600から400にすると並び順セレクトが約295.19 pxから約285.19 pxになりました。長い選択値は全文表示され、高さは35 pxです。日本語のセレクト幅は約250.19 pxで、変更前後が一致しました。
- チケット詳細で投稿欄を開き、保存済みコメントと同じ折り返しを含む文章を入れてから、既存コメントをインライン編集に切り替えました。編集欄の左右の余白は10.5 pxから11.2 pxとなり、投稿欄と揃いました。両欄の上下は9.1 pxで、比較前後で各入力欄の外寸も一致しました。添付の案内と保存・取消ボタンが見える位置で撮影しています。

## 保存と取消

撮影後に日本語・ダークの候補で操作しました。並び順を一時的に「優先度が高い順」へ変更すると、セレクトにフォーカスを保ったままチケットの順序が変わりました。「元に戻す」と設定画面の「キャンセル」で元の順序に戻り、保存済みのAPI応答も一致しました。表示設定を保存すると、並び順と版番号が更新され、残りの設定は同じでした。再読み込み後に選択値とチケット順を再確認しました。

コメント編集を取り消すと保存済み本文はそのままで、再度編集を開くと元の本文が表示されて入力欄にフォーカスしました。合成PNGをブラウザーの貼り付けイベントで渡し、編集を保存しました。再読み込み後に本文と画像を表示し、取得した画像のバイト列を照合しました。投稿欄から新規に保存したコメントも再読み込み後に確認しました。[APIとブラウザーの確認記録](interactions.json)

関連するChromium E2E 12件、公開フロントエンドの型検査、文書ビルドが通過しました。原画像はデスクトップの比較です。画像の貼り付けはブラウザーイベントから検証しました。
