# #1510 GUI全般のページング適用 — 操作・画像エビデンス

## 比較条件

- 対象: Kanban、List、Groupのチケット取得、完了レーンの5件→55件、詳細からの復帰、優先度、200件境界をまたぐ親子、アーカイブ表示。
- Before: `c4ea90458b0cf1652f89a0f589c15e5ee77ec561`（PR #30のキーボード操作を含む）。`kanbalone-keyboard` を専用ポート3590で起動。
- After: `kanbalone-paging` の作業ツリー。採取時のソース指紋は `after-revision.json` に記録する。
- Node v26.13.1、agent-browserのHeadless Chrome、1440×1000、ライトテーマ、日英。ユーザの実データは使用せず、専用DBで比較。
- Fixture: 260件、未完了140件、完了120件（うちアーカイブ2件）。全件同じGroup。親#1と子#205、#2の依存先#240。優先度は7の倍数がurgent、それ以外medium。
- `seed.py` は空の専用インスタンス専用。`fixture-export.json` が取得後の原本。候補は稼働中のbaseline DBからSQLite backup APIで作成した整合バックアップから起動し、ID・時刻・所属を揃える。

## 操作と期待結果

1. Kanbanで完了レーンに5件表示される。50件追加で55件になる。追加操作は既存ボタンを使い、ページ番号など新たなUIは追加しない。
2. 完了チケット#141を開き、Escapeで戻る。55件の展開状態と閲覧位置を保つ。
3. 優先度urgentで絞る。サーバで絞った結果から初期5件を表示し、全体件数を正しく示す。Beforeは55件の表示上限を引き継ぎ17件表示、Afterは条件変更として5件へ戻る仕様。
4. Listで「Verify」を検索。親#1・子#205の2行が関係を保って表示される。
5. Groupに258件が表示され、アーカイブ表示を有効にすると260件になる。親#1・子#205の階層、完了状態、レーン位置が維持される。
6. 検索や表示切替だけではチケットデータを変更しない。`*-persisted.json` で取得前後のexport比較を記録する。

`capture.py` はagent-browserで既存画面を操作する。Groupのアーカイブ切替は長い一覧の下にあるため、focus→Enterで実行する。最初のマウスclick試行ではボタンが動作せず、この試行は最終比較から除外した。画像のピクセル編集は行っていない。

## 証跡

- `before-*.png` / `after-*.png`: 日英20状態ずつ。全画面の元画像。
- `*-trace.json`: 表示ID、件数、焦点、スクロール、一覧APIのresource entry。隠れた別viewのDOMが残るため、比較対象viewの値を使う。
- `*-persisted.json`: 操作前後の保存データ比較。
- `test/e2e/pagination.spec.ts`: bounded requests、200件境界の親子、5→55→同期更新、優先度、失敗時再試行、409回復、最後の完了状態を解除した際に従来どおり両方へ戻る操作、優先度で非表示の依存先、More中の409回復の回帰確認。
- タイミングや永続化はスクリーンショット単体では証明しない。ネットワーク件数・テスト結果・API保存結果を併せて参照する。

## 観測結果

- 初回5件、50件追加後55件、詳細を閉じた後55件。日英ともIDとスクロール位置を確認した。
- List検索は親#1と子#205の2件。Groupは258→260件となり、親子・完了・レーン表示を維持した。
- 優先度を変更した場合だけ、展開状態を初期化する仕様に沿ってBefore17件→After5件となる。残りは既存の追加ボタンで表示できる。
- 画像採取の操作前後で、保存されたボード・チケット・Group情報は一致（`before-persisted.json` / `after-persisted.json`）。
- 観測したGUIのチケット一覧リクエストはすべてlimit付き（5、50、200）。List/Groupは集合を完全取得するため、全体の転送量が減ったとは主張しない。
- 見た目は既存の白いパネル、枠線、ボタン位置、親子インデント、状態アイコンを維持。新たなページ番号や常設設定を追加していない。

最初のE2E試行では、評価用Groupの時刻欠落、重複するフィルタ展開ボタンのselector、依存先のタイトルがtooltipであること、最後の状態解除が「両方へ戻す」既存仕様であることをテスト側で修正した。これらを製品不具合や性能値として集計していない。

## 制限

画像は通常状態の視認性とレイアウト比較を支えるが、回復・同期・永続化は別途E2E/API結果を参照する。実ユーザを対象にした使いやすさ調査、スクリーンリーダー実機、全ブラウザ比較は実施していない。今回の撮影はライトテーマ1440×1000を共通条件とする。

- `e2e-final.txt`: 追加した8ケースすべて成功（2.5分）。日英の全GUIページ取得・親子、展開/同期/優先度、503再試行、Groupの409再取得、最後の完了選択を解除した際の既存動作、絞り込み外の依存先リンク、Moreの409再取得時の105件/スクロール保持を確認。
