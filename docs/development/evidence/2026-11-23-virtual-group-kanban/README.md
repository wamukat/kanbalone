# Group とカンバンの仮想表示

[実装 PR #61](https://github.com/wamukat/kanbalone/pull/61)

Group と「グループなし」は表示対象が1,000行以上、カンバンの通常レーンは表示対象が200枚以上で、見えている範囲と周辺を描画します。件数や並び順は全対象データから算出します。完了レーンの先頭5件と追加ページは従来どおりです。

## 配布ビルドの比較

基準は `e370777b8b5c7fb6501f3208b1d29372e9bc1e5c`、計測した統合版は `f508fa3e5a20f9c2993c89c3d6d6d69fea0c0c2b`（tree `b5667f4d4423c461a66c77a395ae7285ae13c366`）です。各版のアーカイブを同じ `pnpm build` で構築し、専用の配布用バックエンドと静的ファイルを使用しました。Chromium 159.0.8154.6、Node 26.13.1、Intel Core i7-9750H の Mac、1440 × 1000、英語ライト環境です。同じ合成 SQLite のコピーを使い、各版・各条件でウォームアップ1回と集計3回を実施しました。計40回です。

表の値は中央値［最小–最大］msです。可視範囲の比較は、同じ実カードまたは行、タイトル、操作可否と2回の `requestAnimationFrame` を確認した時点です。操作時間はナビ開始から、同じ可視タイトルにフォーカスし、Chromium が実際に発行した Enter で詳細が開き2フレームを経るまでです。自動化の観測、フォーカス、入力の往復を含みます。すべての試行で開いたIDとタイトルを保存済みレコードの GET と照合しました。

統合版は両指標とも15/15回が1秒以内でした。基準版は可視範囲が9/15回、詳細操作が6/15回でした。小規模カンバンでは詳細操作中央値が約48ms増え、両版の観測範囲が重なりました。小規模カンバンだけは統合版でも初期対象313枚すべてがDOMに存在し、全DOMと2フレームの中央値は436ms → 412msでした。他の統合版では全対象を取得して並び順を保持し、全DOMの完了値はありません。

データ受理の中央値は Group 1,000で200 → 203ms、Group 10,000で475 → 488ms、グループなし10,000で465 → 453ms、カンバン313枚で188 → 189ms、カンバン3,005枚で348 → 369msでした。受理済みの全ID列と、表示モデルの順序を分けて照合しました。全比較で可視ID・タイトル・操作可否・矩形は一致し、観測した配布用JavaScript、CSS、アイコンの応答は可視範囲の確定前に完了しました。数値、ハッシュ、実キー時刻は [計測記録](measurements.json) にあります。

可視判定の幾何測定は先頭から最初の画面外行までです。DOMの完了判定にはライブコレクションの件数を使い、全ID列への展開は計時後に行いました。同じ基準版でも、可視判定を入れていない今回のウォームアップの全DOMは Group 10,000で4.392秒、グループなし10,000で4.848秒でした。以前の別セッションで得た約2.8秒には今回と異なる観測条件があります。今回の値は同一セッションの比較に使い、セッション間の差を特定の原因には帰属できません。ナビから詳細を開く時間は、最早の操作可能時刻やINPの推定には使えません。

### 再現

1. [合成データ生成器](../2026-11-23-tag-render/prepare.mjs) を `node --import tsx` で実行します。`KANBALONE_RENDER_OUTPUT` に新規ディレクトリを指定し、その `fixtures.json` を `KANBALONE_FIXTURE_CATALOG` に設定します。`kanban-high-active` は通常6レーンに3,000枚と、完了レーンの初期5枚を表示します。
2. 計測した統合版のコミットは証拠を追加する直前の内容です。両コミットが見えるリポジトリで、統合版を隔離したクリーンな worktree にチェックアウトします。リポジトリ指定の Node、pnpm、依存関係と Chromium を用意します。
3. 証拠ファイルがあるチェックアウトから `node docs/development/evidence/2026-11-23-virtual-group-kanban/bench-compiled.mjs WORKTREE EXACT_HEAD docs/development/evidence/2026-11-23-virtual-group-kanban/hooks.json` を実行します。計測コードはアーカイブのコピーにだけ入ります。新しい `coverage/virtual-bench/compiled-*` の `raw.json` を `summarize.py` で集計します。

原画像の基準は `e370777b`。Groupの候補画像は `7522ab3`、カンバンは `df63ad5` の配布ビルド時点です。後続の `f508fa3` は詳細を閉じた後の共有フォーカス復帰だけを補正しました。統合版ビルドから Group 10,000 の #1002 とカンバン3,005枚の #1 を開閉し、復帰した可視位置も別途画像で確認しました。原画像のSHA、実decode結果、再現条件、保存GETは [Groupの操作記録](group-interactions.json) と [カンバンの操作記録](kanban-interactions.json) にあります。

初回の統合 Chromium は28/29件。失敗した操作の追跡をきっかけに、詳細を閉じた直後、実SSE更新を待つ間に Tab で別カードを選び、応答後に元カードへフォーカスが戻る問題を再現しました。修正後、同一レーンと別レーンの更新、レーン末尾へのShift+Tab、GroupとListの詳細復帰を含む8件が成功しました。統合の `pnpm check` は270件を通過し、修正後の公開JSとTypeScriptの型チェックも通過しました。 [修正前後の実行ログ](focus-race.txt)
