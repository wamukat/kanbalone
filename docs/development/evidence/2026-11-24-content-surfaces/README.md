# チケット本文・コメント・履歴の共通CSSを検証

チケット本文、コメント一覧、履歴一覧の面と、コメント・履歴の日時や補足行で、値の等しいCSS宣言をまとめた。ダークの本文とMarkdownリンクには、前段で是正した配色を引き継いでいる。

2026-11-24にmacOS 26.7.3、agent-browser 0.26.0とHeadless Chrome 158で取得。言語は日本語、画面は1440 × 900 CSS px、画素比1、動きを減らす設定。チケット1件、本文のリンク、複数行にわたるコメント2件、補足付きの履歴イベントを含む合成DBを複製した。

チケット詳細を開き、本文と既存コメントが出揃った状態で撮影した。次に「履歴」タブを選び、補足付きの履歴が表示された時点で撮影した。テーマごとに同じ操作を繰り返し、PNGを無加工で保存した。各組の全画面をImageMagickの絶対画素差（AE）で比較した。

変更前はダークモード是正を含む `5585cbb`。編集前に退避した公開ファイルを、変更後とは別のサーバーで使用した。二つの公開ツリーで差があるのは対象の2 CSSのみ。変更前後のCSS、原画像の指紋と測定条件を記録した。[測定記録](manifest.json)

## 表示と操作

- 日本語1440 × 900の明暗と英語ダーク820 × 900で、閲覧、履歴選択、コメント投稿欄、コメント編集、本文編集を比較した。15条件で描画領域を持つ要素378サンプルで、computed styleの全プロパティ、位置、寸法、フォーカスが一致した。本文の折返し、一覧の区切り、補助色、リンクの前景を含む。
- 英語ダーク820 × 720でコメント欄にフォーカスし、下までスクロールしてCtrl+Enterで投稿した。既存コメント2件に1件が追加され、編集取消では保存値が保たれた。再編集の保存、履歴とコメントの切替、再読込後の表示とAPI再取得を確認した。各試行の書き込みはPOSTとPATCH各1回で、元の本文とコメント2件は保持された。
- 最初の狭幅試行では、投稿欄を開いたまま編集を始めた直後のスクロール位置に差があった。投稿欄を閉じて同じ位置から再試験すると両版それぞれ2回で一致した。投稿欄を開いたまま同じスクロール位置から操作する再試験でも、編集開始直後の座標は同一版の反復内で揺れた。フォーカス、スクロール領域の高さ、タブ切替後の位置と保存結果は一致した。中間のスクロール座標は固定値として扱わない。
- 関連Chromium E2Eは20件が成功した。初回19件が成功し、コンテキスト終了時に制限時間を超えたインライン更新の1件は、既定の制限時間で単独再実行して成功した。Webビルドと公開フロントエンドの型検査も通過した。[詳細と履歴](../../../../test/e2e/ticket-detail-inline.spec.ts)・[配色](../../../../test/e2e/layout-visual-system.spec.ts)・[投稿と編集](../../../../test/e2e/ui-smoke.spec.ts)

画像は閲覧時の代表条件。入力とフォーカスは別に測定した。外部サービスへのコメント送信や、Chromium系以外のブラウザーは今回の確認範囲外。
