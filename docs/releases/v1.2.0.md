# v1.2.0

## 日本語

前の安定版 v1.1.0 からの変更です。

### 変更点

- 大規模な Kanban と Group では、表示領域周辺のカードや行を描画し、スクロールに合わせて描画対象を更新します。Kanban は通常レーンに表示対象が200枚以上、Group と「グループ指定なし」は表示対象が1,000行以上の場合に仮想表示を使います。完了レーンは引き続き必要に応じて追加のカードを読み込みます。
- Kanban の検索では現在の絞り込みに含まれるチケットを検索できます。大規模な Group と「グループ指定なし」では、チケット検索で表示範囲外の行もタイトルや `#ID` で見つけ、前後の一致へ移動できます。Tab と Shift+Tab は表示範囲の境界を越えて移動できます。macOS ではブラウザが Option+Tab を受け取る場合も移動先を準備します。詳細を閉じた直後に別の項目へ移動した場合、新しいフォーカスを保ちます。
- Kanban で表示範囲をまたいでカードを移動できます。仮想表示のレーンがあるボードで、移動元のレーンや位置、挿入先の基準カードの所属や相対順序がドラッグ中に変わった場合は、保存時に検出してボードの最新状態を読み込みます。小規模レーンでドロップ先を受け付ける処理も WebKit で改善しました。Group は表示領域のサイズが変わったときに末尾位置を維持します。
- ブラウザに配信する JavaScript と CSS のリクエストをまとめました。Group と List の初期取得や関係候補のページ取得、Kanban と Group のアイコン描画、Kanban のライブ更新、チケットの移動やアーカイブにかかる処理を削減しました。Group で既存チケットを追加する際の候補選択と、詳細表示を開く際のレスポンスも改善しました。
- 強制カラーモードで Group 検索の現在の候補をアウトラインで示します。ダークテーマのチケット詳細ではレーン名が読みやすくなり、確認ダイアログの本文にもテーマのテキスト色を適用します。

### 更新時の注意と制約

- 更新前にアプリとほかのデータベース書き込み元を停止し、SQLite と添付画像をまとめてバックアップしてください。起動時にチケットの位置順取得用の索引を追加し、ページングの更新検出用トリガーを更新します。旧版へ戻す場合は、旧イメージと更新前のバックアップを組み合わせてください。復元にはバックアップ後の変更は含まれません。[データベースと画像のバックアップ](https://github.com/wamukat/kanbalone/blob/v1.2.0/docs/ja/migration-guide.md#database-and-image-backup)
- チケット一覧の既存 API 呼び出しはそのまま使えます。Group 行と List 参照用の軽量ページ API を追加しました。ページ取得中に一覧の変更を示す `409` が返った場合は、先頭から取得し直してください。移動 API では `expectedSourceLaneId` と `expectedSourcePosition` を組み合わせて任意に指定できます。この条件を使用し、前後両方の基準カードを指定する場合は、その時点のデータベース上の相対順序を `expectedAnchorOrder` に指定します。移動元の位置、基準カードの所属や相対順序が変わっていれば `409` が返り、移動は保存されません。これらの条件を省略した既存の移動リクエストは従来どおり動作します。[API リファレンス](https://github.com/wamukat/kanbalone/blob/v1.2.0/docs/openapi.yaml)
- 仮想表示ではブラウザ標準のページ内検索は描画済みの範囲が対象です。表示範囲外のチケットには、Kanban または Group の検索欄を使用してください。[ユーザーガイド](https://github.com/wamukat/kanbalone/blob/v1.2.0/docs/ja/user-guide.md)

## English

Changes since the previous stable release, v1.1.0.

### Changes

- Large Kanban and Group views render cards and rows around the viewport and update which ones are rendered as you scroll. Kanban uses virtual rendering for regular lanes with at least 200 cards to display. Group and No Group use it at 1,000 rows. Completion lanes still load more cards on demand.
- Kanban search covers tickets within the current filters. In large Group and No Group views, search by title or `#ID` and step through all matches, including rows outside the viewport. Tab and Shift+Tab can cross rendered windows. On macOS, the app also prepares the destination when the browser delivers Option+Tab. If you move to another control while a ticket detail is closing, your new focus is preserved.
- Kanban supports dragging cards beyond the currently rendered window. On boards with a virtual lane, Kanban detects changes to the source lane or position and to the destination anchors’ lane membership or relative order at save time, then reloads the board if there is a conflict. Drop acceptance in small lanes also improved in WebKit. Group keeps the bottom in view when the display area changes size.
- The built app bundles JavaScript and CSS into fewer browser requests. Group and List fetch less data, relation candidate pages need less work, and Kanban and Group render lighter icons. Kanban does less work on live refreshes, and moving or archiving tickets in large lanes takes fewer database operations. Keyboard selection when adding existing tickets to a Group and opening ticket details also take less work.
- An outline marks the current Group search result in forced colors mode. The lane name in ticket details is easier to read in dark mode, and confirmation dialog text follows the active theme.

### Upgrade notes and limitations

- Before upgrading, stop Kanbalone and other database writers, then back up SQLite and its attachments together. On startup, Kanbalone adds an index for position-ordered ticket queries and updates the triggers that track changes to paged ticket lists. For rollback, use the previous image with the pre-upgrade backup. Restoring it recovers the data as of the backup. [Database and image backup](https://github.com/wamukat/kanbalone/blob/v1.2.0/docs/en/migration-guide.md#database-and-image-backup)
- Existing ticket list API calls continue to work. New lightweight paged APIs expose Group rows and List references. If a page returns `409` because the list changed, start again at the first page. The move API accepts the optional pair `expectedSourceLaneId` and `expectedSourcePosition`. When both destination anchors are supplied for a guarded move, set `expectedAnchorOrder` to their relative order in the database. Changes to the source position or to the destination anchors' membership or relative order cause a `409`, leaving the move unsaved. Calls that omit these conditions keep the previous behavior. [API reference](https://github.com/wamukat/kanbalone/blob/v1.2.0/docs/openapi.yaml)
- With virtual rendering, the browser's Find command searches the rendered content. To reach tickets outside that area, use the search field in Kanban or Group. [User guide](https://github.com/wamukat/kanbalone/blob/v1.2.0/docs/en/user-guide.md)
