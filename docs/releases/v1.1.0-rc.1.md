# v1.1.0-rc.1

## 日本語

v1.1.0のリリース候補です。以下は安定版v1.0.0からの変更です。この候補を公開してもDockerの`latest`はv1.0.0のままです。

### 変更点

- チケット本文やコメントの編集欄に画像をドロップまたは貼り付けると、カーソル位置に画像のMarkdownを挿入します。PNG、JPEG、GIF、WebPに対応し、上限は1ファイル10 MiBです。同じ画像データは1つのファイルを共有します。
- Group一覧に完了割合と全件完了時のチェックを表示します。未完了のままアーカイブしたチケットは完了件数に加えません。Group内の親・子チケットにタグを表示し、説明リンクの色をテーマに揃えました。未所属のチケットは「グループ指定なし」から確認できます。
- KanbanとListでは、検索欄で↓を押し、矢印キーでチケットを選び、Enterで開けます。Escで元のチケットとスクロール位置に戻ります。チケットのタイトルや選択中のGroup名にフォーカスしてNを押すと、新規作成画面を開きます。Kanbanでは元のチケットと同じレーン、ListとGroupでは最初のレーンが初期値です。Groupでは表示中のGroupも選択されます。Ctrl+Enter（Macでは⌘+Enter）で保存できます。
- 完了レーンは表示する分を順次取得します。Listの一括選択、Groupの表示・更新、ボードの初期読み込みを効率化しました。親・子・ブロッカーなどの候補は最初の検索時に、候補表示に必要な項目だけ取得します。ダークテーマで編集欄の見出しを読みやすくしました。
- チケット一覧APIに任意のカーソルページング、優先度フィルター、並び順を追加しました。関連チケット候補用API、画像の登録・取得API、Groupの`resolvedTicketCount`も追加しました。[APIの呼び出し例](https://github.com/wamukat/kanbalone/blob/v1.1.0-rc.1/docs/ja/api-examples.md#チケット一覧のページング)

### 更新時の注意と制約

- 既存のチケット一覧APIを`limit`と`cursor`なしで呼び出した場合は、全件取得・既定の順序・応答形式を維持します。ページングを使う場合は、一覧変更による409で取得途中のページを破棄し、先頭から取り直してください。
- 画像を参照するボードのJSON Exportは`formatVersion: 3`となり、画像を同梱します。v1.0.0以前への取り込みには対応していません。Exportを処理するスクリプトも形式3に対応してください。画像を参照しないボードは形式2のままです。旧形式と形式2のImportは引き続き利用できます。Base64画像を含むJSON全体の上限は64 MiBです。超える場合はDBと画像のバックアップを使ってください。
- 更新前にアプリとほかのDB書き込み元を停止し、候補版に同梱のツールで整合したバックアップを作成してください。旧DBも対象です。ファイルを直接コピーする場合は、停止中のSQLite本体、存在する`-wal`・`-shm`、同じディレクトリの`attachments/`を一組として保存します。起動時にページング用のテーブル・トリガー・索引と添付画像の管理テーブルを追加します。更新後はSQLiteと画像ファイルを永続化し、同梱のバックアップツールで一緒に保存・復元できます。旧版へ戻す場合は、旧イメージと更新前のバックアップを組み合わせてください。復元にはバックアップ後の変更は含まれません。[データベースと画像のバックアップ](https://github.com/wamukat/kanbalone/blob/v1.1.0-rc.1/docs/ja/migration-guide.md#database-and-image-backup)
- 画像はローカル保存です。外部サービスへ添付ファイルとして送信する機能と、編集の取り消しや参照削除後に未参照ファイルを自動削除する機能はありません。List・Groupは表示対象を全件読み込み、関連チケットの初回候補検索はアーカイブ済みを含むボード全件から候補を取得します。大規模ボードでは時間がかかる場合があります。

## English

This is the v1.1.0 release candidate. The changes below are relative to the stable v1.0.0 release. Publishing this candidate leaves the Docker `latest` tag at v1.0.0.

### Changes

- Drop or paste an image into a ticket body or comment editor to insert its Markdown at the cursor. PNG, JPEG, GIF and WebP are supported, up to 10 MiB per file. Identical image bytes share one file.
- The Group list shows completion progress and a check when every ticket is resolved. Archived tickets that are still open are excluded from the resolved count. Parent and child tickets display their tags, and description links follow the theme. Choose **No Group** to see unassigned tickets.
- In Kanban and List, press ↓ in search, use the arrow keys to select a ticket, and press Enter to open it. Esc returns to the ticket and scroll position. Press N on a ticket title or the selected Group name to open the creation dialog using the focused ticket’s lane in Kanban or the first lane in List and Group. In Group view, the displayed Group is selected. Save with Ctrl+Enter (⌘+Enter on Mac).
- Completion lanes fetch more tickets as needed. List bulk selection, Group rendering and updates, and initial board loading do less work. The first search for child, parent, blocker or related tickets fetches only the fields needed by the picker. Editor headings are easier to read in dark mode.
- The ticket list API adds opt-in cursor pagination, priority filtering and explicit ordering. There are also APIs for relation candidates and local images, and a `resolvedTicketCount` field for Groups. [API examples](https://github.com/wamukat/kanbalone/blob/v1.1.0-rc.1/docs/en/api-examples.md#paged-ticket-lists)

### Upgrade notes and limitations

- Existing ticket list calls that omit `limit` and `cursor` keep their full result set, default order and response shape. When a paged request returns 409 because the list changed, discard the partial collection and start again.
- A board JSON export that references local images uses `formatVersion: 3` and includes the image files. Importing format 3 requires this candidate or a later compatible version. Update scripts that read exports to handle format 3. Boards without local image references still export in format 2. Legacy and format 2 imports remain supported. The 64 MiB limit applies to the entire JSON payload, including Base64 image data. Use a database and image backup for larger transfers.
- Before upgrading, stop the app and other database writers. Use the candidate’s bundled backup tool to take a consistent backup, including from older versions. When copying files directly, keep the stopped SQLite database, any `-wal` and `-shm` files, and the sibling `attachments/` directory together. Startup adds pagination tables, triggers and indexes, plus image attachment metadata. Keep SQLite and the image directory on persistent storage and use the bundled tool to back them up and restore them as a set. To roll back, use the previous image with the pre-upgrade backup. The restored data reflects the time of that backup. [Database and image backup](https://github.com/wamukat/kanbalone/blob/v1.1.0-rc.1/docs/en/migration-guide.md#database-and-image-backup)
- Images are stored locally. The app does not upload them as attachments to external issue trackers or automatically delete files after a cancelled edit or removal of a reference. List and Group still load every matching ticket. The first relation candidate search loads candidates from the whole board, including archived tickets. Both can take time on large boards.
