# v1.0.0-rc.1

## 日本語

v1.0.0に向けた最初のリリース候補です。以下はv0.11.0からの変更です。安定版としての受け入れ確認は継続中です。

### 変更点

- カンバン／リストの完了状態とアーカイブ表示を分けました。**完了状態** は従来と同じ横展開で選び、**アーカイブを含める** で表示範囲を切り替えます。リストでレーンと完了状態が合わない場合は、理由と条件を変更する操作を表示します。

- カードがあるレーンへのドラッグが保存されない場合を修正しました。ドラッグ中は挿入位置を示し、キャンセル時は元の位置を保ちます。

- 完了レーンは最近完了した5件を表示し、50件ずつ追加表示できます。移動したチケットは先頭に残ります。Kanban／Listの初期表示は未完了＋完了とし、保存済みの未完了・完了の選択は保持します。
- Group内の完了チケットを控えめに表示し、完了・アーカイブのアイコン位置を揃えました。
- APIに読み取り専用の完了日時 `resolvedAt` を追加しました。過去の日時が不明なチケットは `null` のまま保持します。

- UIを日本語・英語に対応しました。歯車パネルの言語設定で切り替えられます。初回はブラウザの言語を使い、選択はそのブラウザに保存します。チケット本文やボード名は翻訳しません。
- 編集中の未保存内容を破棄する際の確認を追加し、ボード移動後のレーン選択・本文保存を改善しました。
- チケット詳細に現在のレーン、Kanbanに未完了ブロッカーの件数を表示します。Markdownのタスクリストもチェック状態を表示します。
- 検索結果がない場合や表示対象のGroupがない場合に、状態と次の操作を案内します。狭い画面の初期サイドバー表示、復元・Export後の案内、重複Import時の既存チケットへのリンクも改善しました。
- 配布用ソースアーカイブから開発者向けスキルを除外しました。利用者向けの`skills/kanbalone-api`は引き続き配布します。Dockerイメージにスキルは含まれません。
- リリース準備・テスト・イメージ検証・公開をGitHub Actionsへ統合しました。旧版からの更新、WALを含むバックアップ、旧版への復元を公開前に自動検証します。

### APIの破壊的変更

非推奨だった互換APIを削除しました。既存のスクリプトやAIスキルは更新前に対応してください。

| 削除した仕様 | 対応方法 |
| --- | --- |
| レスポンスと新規Exportの`isCompleted` | 読み取り専用の`isResolved`を使用 |
| 検索条件`completed` | `resolved`を使用。旧条件は400 |
| 作成・更新・transition・bulk-transition・previewで渡す`isResolved` / `isCompleted` | 両方を省略し、`laneId`または`laneName`で移動先を指定。旧入力は400 |
| `POST /api/boards/:boardId/tickets/bulk-complete` | `POST /api/boards/:boardId/tickets/bulk-transition`を使用。旧エンドポイントは404 |
| `POST /api/boards/:boardId/tickets/reorder` | チケット単体の`PATCH /api/tickets/:ticketId/position`、またはレーン内の`POST /api/lanes/:laneId/tickets/reorder`を使用。旧エンドポイントは404 |

完了状態は移動先レーンの`isCompletionLane`で決まります。レーン名だけで判断しないでください。レーンをまたぐ複数の並べ替え要求は、ボード全体で1つの原子的操作にはなりません。

### 更新時の注意と制約

- 保存済みのアーカイブ表示条件を新しい形式に変換します。完了状態はアーカイブ済みにも適用されるため、表示対象が変わる場合があります。[移行ガイド](../ja/migration-guide.md)で変換内容を確認してください。
- v0.11.0からの更新では、新たな完了状態の再分類やGroupの再割り当ては行いません。旧版DBの移行と旧ExportのImportは引き続き対応しています。
- 更新前に書き込みを止め、SQLiteのDB・WAL・SHMを一式バックアップしてください。旧版へ戻す際は旧イメージと更新前バックアップを組み合わせます。バックアップ後の変更は復元されません。JSON ExportはDB全体のバックアップの代わりにはなりません。
- AI環境にインストール済みの`kanbalone-api`スキル・参照・ヘルパーも更新してください。リポジトリの更新だけでは、インストール済みスキルは変わりません。
- 更新検証の対象はv0.9.35・v0.10.0・v0.11.0からのLinux/amd64 Docker（volume／bind mount）の代表経路です。全旧版、ネイティブ／ARM環境、実プロバイダーの認証や障害条件を網羅するものではありません。
- このRCの公開時に安定版の`latest`は変更しません。既存の稼働環境も自動更新されません。

詳しい入力の書き換えと復元手順は[移行ガイド](../ja/migration-guide.md#deprecated-api-removal)を参照してください。

## English

This is the first release candidate for v1.0.0. The changes below are relative to v0.11.0. Acceptance for the stable release is still in progress.

### Changes

- Separated completion state from archive visibility in Kanban/List. **Completion** keeps the existing inline expansion; **Include archived tickets** controls archive visibility independently. List explains incompatible lane/completion selections and offers actions to adjust them.

- Fixed ticket drags into occupied lanes not being saved. Dragging now shows an insertion marker and cancellation preserves the original position.

- Completion lanes show the latest five tickets, with 50 more available per click. Newly completed tickets appear first. Kanban/List initially show open and resolved tickets; saved open/resolved selections are preserved.
- Completed Group tickets use subdued text, with aligned completion and archive icons.
- Added read-only completion timestamp `resolvedAt` to the API. Existing tickets with unknown completion times retain `null`.

- Added Japanese and English UI support. Choose a language in the gear panel. The first visit follows the browser language; subsequent choices are saved in that browser. Ticket content and board names are not translated.
- Added confirmation before discarding unsaved edits and improved lane selection and body saving after moving a ticket between boards.
- Ticket details show the current lane, Kanban shows unresolved blocker counts, and Markdown task lists display checked and unchecked states.
- Empty search results and Group views explain their state and offer a next action. Improvements also cover the initial sidebar on narrow screens, restore/export feedback and links to existing tickets during duplicate import.
- Consumer source archives exclude development-only skills. The user-facing `skills/kanbalone-api` remains included. Docker images do not contain skills.
- Release preparation, checks, image verification and publication now run through GitHub Actions. Upgrades from older releases, WAL-inclusive backups and restoration to the original release are automatically tested before publication.

### Breaking API changes

Deprecated compatibility APIs have been removed. Update existing scripts and AI skills before upgrading.

| Removed behavior | Replacement |
| --- | --- |
| `isCompleted` in responses and new exports | Read-only `isResolved` |
| `completed` query filter | Use `resolved`; the old filter returns 400 |
| `isResolved` / `isCompleted` inputs in create, update, transition, bulk-transition and preview requests | Omit both and select a destination with `laneId` or `laneName`; old inputs return 400 |
| `POST /api/boards/:boardId/tickets/bulk-complete` | Use `POST /api/boards/:boardId/tickets/bulk-transition`; the old endpoint returns 404 |
| `POST /api/boards/:boardId/tickets/reorder` | Use `PATCH /api/tickets/:ticketId/position` for one ticket or `POST /api/lanes/:laneId/tickets/reorder` within a lane; the old endpoint returns 404 |

Completion follows the destination lane's `isCompletionLane`, not its name. Multiple ordering requests across lanes do not form one atomic board-wide operation.

### Upgrade notes and limitations

- Saved archive filters are converted to the new format. Completion filters now also apply to archived tickets, so the visible set may change. See the [migration guide](../en/migration-guide.md) for conversion details.
- Upgrading from v0.11.0 does not reclassify completion or reassign Groups. Older database migrations and legacy export import remain supported.
- Stop writes and back up the SQLite DB, WAL and SHM together before upgrading. To roll back, use the original image with the pre-upgrade backup. Changes made after that backup are absent from the restore. JSON export is not a full database backup.
- Update the `kanbalone-api` skill, reference and helper installed in each AI environment. Updating the repository does not update installed copies.
- Upgrade verification covers representative Linux/amd64 Docker paths from v0.9.35, v0.10.0 and v0.11.0 using volumes and bind mounts. It does not cover every historical release, native/ARM deployments, live provider authentication or every failure condition.
- Publishing this RC does not change the stable `latest` tag or automatically update an existing running instance.

See the [migration guide](../en/migration-guide.md#deprecated-api-removal) for request rewrites and restoration steps.
