# 人とAIで、仕事の続きを進める

Kanbaloneは、AIと開発する個人のためのローカル作業スペースです。
**登録もログインも不要。課題管理はローカルで完結し、自分のPCで気軽に始められます。**
Dockerが使える環境なら、コマンド一つで起動。ブラウザでボードを作れば、ほとんど設定なしですぐ課題管理を始められます。
外部トラッカーやAIとの連携は、必要に応じて選べます。
外部の依頼を手元の作業に落とし込み、調べたこと、実装方針、進捗を同じ場所に残します。
人は画面から、AIはAPIから、その続きを進められます。

## こんな負担を減らしたい人へ

Issue、AIとの会話、手元のメモを行き来しながら開発している人。
作業を再開するたびに経緯を探し直したり、AIに説明し直したりする負担を減らしたい人。
チームの課題管理はそのまま使い、自分の試行錯誤や細かい作業を手元で整理したい人に向いています。
外部Issueを使わず、自分の作業から始めることもできます。

## 依頼を受け取り、手元で深め、成果を返す

たとえば、不具合のIssueを取り込んだら、原文を参照しながらローカル本文に調査内容と実装方針を書き足します。
AIが作業経過と確認結果を記録し、人は残件や受け入れ待ちの作業を確認します。
共有したい報告だけを外部へ返せるので、試行錯誤をすべて公開する必要はありません。

GitHub Issues・GitLab・Redmineからの取り込みに対応します。外部の原文を更新しても、ローカル本文は保持されます。外へ送る対象は選択したコメントです。

## 三つの価値

**説明し直す負担を減らす。** 目的、調査、作業経過をチケットに残し、人にもAIにも引き継げる形にします。会話が終わっても、仕事の記録は手元に残ります。

**自分の作業を、自由に深める。** 共有された依頼とローカルの実装メモを分け、必要な報告を選んで返せます。チーム全体の管理方法を変える必要はありません。

**今、見るべき仕事をつかむ。** 作業段階、目的ごとの残件、受け入れ待ちを見渡せます。AIにはAcceptanceへ渡してもらい、人が確認して完了レーンへ移す運用もできます。

目的ごとの作業はGroupでまとめられます。親子の所属を揃え、終わった作業の経緯を残しながら、次に進める残件を見渡せます。

## 大切にする使い心地

思いついたらすぐ記録し、必要な仕事を探し、次の操作へ迷わず進めることを大切にします。
日常の画面は静かに保ち、管理のための設定や操作を増やしすぎません。
現在の開発版では、`N`で新規作成画面を開き、`/`で検索へ移動し、カンバン・リストでは矢印とEnterでチケットを開いて戻れます。`M`でレーンを選択し、Ctrl＋Enter（Macは⌘＋Enter）で確定できます。キーの有効範囲と取消・保存の動きは[操作ガイド](user-guide.md#キーボードで探して開く)にまとめています。

操作の発見しやすさや、実利用者がどれだけ少ない手間で作業できるかは、引き続き評価する対象です。

ここでいう「軽さ」は、覚えるルールと操作の負担が少ないことです。処理速度が他製品より速いという比較結果ではありません。

## 適した使い方

一人の開発者と、その人が利用するAIツールの作業場所として設計しています。
組織の権限管理、担当者ごとの承認強制、工数集計を中心に管理したい場合は、それを担う課題管理製品を利用してください。
Kanbaloneの受入は運用上の区切りであり、人だけが完了にできる権限機能ではありません。

AIの自動実行や会話の自動記憶を提供する製品でもありません。残した作業情報を人とAIが利用する仕組みです。
データはローカルに保存されますが、外部への送信や、接続するAIがデータをどう扱うかは利用する操作・ツールによります。
