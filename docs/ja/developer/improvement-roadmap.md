# v1.0後の改善状況と残る評価

初稿: 2026-11-22。更新: 2026-11-28。実装確認の基準はmain `92571d1e2fcef1a37d630fa02733e7f2c2ce0b83`。ソースへの実装、比較実験、実利用者による評価、リリースを分けて記録する。本書の実装済み項目を、公開済みv1.6.0や利用中の環境へ反映済みとは扱わない。

## 目指す体験

**人が読む・判断する・少し書く操作と、AIが文脈を取り出して更新する操作の両方を軽くする。**

初稿では新規チケット作成と検索を優先した。現在はその入口と一覧からの移動、レーン変更、変更内容の表示が実装されている。次の仕事は同じ入口を作り直すことではなく、残った使いにくさと未測定の効果を確認することになる。Groupは分類機能を増やすだけでなく、目的・経緯・残件を少ない説明で共有できるか評価する。

## 次に進める順序

### 1. 未完の問題を現行版で絞り込む

2026-11-28の確認では、[UI/UX評価の管理Issue](https://github.com/wamukat/kanbalone/issues/95)の配下に、カスタムビュー、Group表示、ボード設定、アーカイブ、フォームやスマホ幅などの残件がある。たとえば[本文チェックリスト #105](https://github.com/wamukat/kanbalone/issues/105)はTask追加だけでは完了しない。[MR/PR状態 #14](https://github.com/wamukat/kanbalone/issues/14)も、外部リンクの登録とは別の残件である。

Issueの状態は変わるため、着手時に一覧と現行動作を再照合する。過去の提案を一括実装したり、古い完了条件だけで再開したりしない。新しいUI判断は既存部品・位置・アイコン中心の表示を保ったモックで確認し、チケットごとに同条件の前後画像と操作・保存結果を添付する。

### 2. 作成・検索・確認の効果を測る（P01/P03/P04）

- 現行版で100件・1000件の合成データから始める。5000件は必要な場合の負荷確認とし、均一データと長文・多数コメント・親子・Group混在を分ける。
- 検索入力→結果確定、詳細→本文を読めて入力可能、保存→完了表示と再取得の一致を終点にする。前景タブ、viewport、キャッシュ、完了判定を揃え、通信・DOM更新・アニメーションを分ける。
- 中央値・p95、取得件数・転送量、長い処理とエラーを記録する。ツール呼出し時間や探索用待機を利用者の操作時間に足さない。
- 実利用者では初回学習と反復を分け、打鍵数、マウスへの持ち替え、誤対象更新、下書き消失、説明を探す負担を確認する。機械テストの成功から生産性向上を推定しない。

完了条件は、同じ手順を再実行でき、改善した／しなかった範囲を説明できること。数値目標は測定後に決める。すでに存在する仮想化を「導入候補」として重複計画しない。空レーン折り畳み、別のキャッシュや楽観更新は必要性が確認されたときに個別検討する。

### 3. 更新と再取得の境界を追加確認する（P02）

- 古い画面とAPIが同じ項目を編集する場合と、別項目を変更する場合を分ける。本文・レーン・Group・Task等で使う競合契約も区別する。
- タイムアウト、成功後の再取得失敗、再試行、ドラッグ中の更新、ブラウザの比較基準の保存失敗を検証する。実装済みガードを別経路で迂回しない。
- API再取得・再読込と時系列で確認し、誤対象更新・二重送信を平均速度で隠さない。既存回帰が扱っていない条件を明示する。

実外部サービス障害、実スクリーンリーダー、実利用者評価、Preview進行表示などの後続事項は、この文書更新では完了にしない。環境や参加者が必要な確認と、ローカルで再現できる回帰を分ける。

### 4. Groupと外部トラッカーの価値を比較する（P05/P06）

Groupでは前の会話を渡さず、既存APIから目的・親子・残件・コメントを取得して「次の作業」「確認済み」「未確認」を答えられるか比較する。正解を用意した合成シナリオで、Groupなし／既存Group／説明の書き方改善を分け、見落とし、追加質問、API往復、取得量、再開時間を記録する。独立実行者を使う場合は、その範囲を作業計画で明示する。

外部連携は、隔離したRedmine単独とRedmine＋Kanbaloneで原文更新・手元の検討・受入・選択報告を比べる。原文保持だけでなく二重管理や報告漏れも数える。今回の過去実験は各製品単独のGUI/API往復であり、この併用比較を済ませたものではない。

取得の手間だけが障害なら既存スキルや読み取り集約を比較し、新フィールド・自動AI要約・接続先追加を先に決めない。Jira取り込みを開発予定として本書で追加しない。

## 合意の履歴と実装判断

2026-11-22には新規作成／検索の優先と共通検索の検討に合意した。これは当時の検討開始の合意であり、独立検索ダイアログの実装決定ではなかった。その後の実装は既存検索へのフォーカス、一覧移動と復帰、文脈を引き継ぐ作成、Group検索、同ボードレーン移動へ進んだ。現在の操作契約を基準とし、旧「次のモック」の案を未着手の必須作業として扱わない。

Groupの単一所属、親子の所属統一、ボード内限定、残件由来のActive、移動時の「解除→追加」を維持する。承認ワークフロー、チーム権限、Group階層、複数Group所属、汎用コマンドパレットは今回の改善範囲ではない。

## PRとリリースの区切り

- 発見した不具合と新しい操作仕様を分け、短命ブランチとレビュー付きPRにする。実装済み／検証済み／未確認をPRで明記する。
- UIはチケットごとに日英、同じデータ・viewport・状態の前後画像と保存の再確認を残す。独立レビューと人の受入を区別する。
- Required checksとチャット受入後にマージする。リリースは[リリースガイド](release.md)に従い、日英ノート、候補検証、公開許可を別に確認する。
- P05/P06を全て終えるまで公開を待つという計画ではない。公開バージョンや通常環境の更新を、この文書だけで決めない。
